# Alignment to the DoD data mesh reference (AL-DMRA)

This record sets the mesh against the principles and services of the DoD data mesh reference architecture, one row per element. It uses the alignment shape in [the README](../README.md), and statuses and pins are as listed there. The shape is provisional.

**This record describes; it proposes nothing.** Where it names something unbuilt, the row's status says so.

## The reference

| | |

| Edition | version 2.6, March 2024 |
| Terms | Public. Cited by element name and section only. No figure or passage is copied, and each element's meaning is given here in this record's own words. The document is not committed. |
| Elements used | §4 "Principles": the four generic mesh principles and the fifth principle the reference adds. §3 "Tactical Structure": the fifteen services. §4 "Capability Patterns": items 1 to 15, one per service. The Capability column is read against a second reference: NATO DCRA v2, AC/322-D(2025)0056, Appendices 1 to 13, by title only. |

## Summary

- **Close:** one service, data exchange (S7), through the gateway, broker and client, with the data-plane gaps it names. Policy access control (S5) is binary as described, but it decides on relations, not attributes, so it is `partial`.
- **Different:** one service, mediation (S14). Translation happens once, at the producer, not per consumer.
- **Partial:** most rows. The mesh has the piece each service is built around but not the whole of it. Each row names the missing part.
- **None:** the mesh has no pub/sub. Its phase is `proposed`.
- **Two gaps are set by the lane's rules and stay gaps until code shows otherwise:**
  - catalog metadata is not published in DCAT form (row S3);
  - security labels are not published in a standard label metadata form (row S12).
